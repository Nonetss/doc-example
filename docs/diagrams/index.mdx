## Declarado, no dibujado

Un diagrama dice qué cajas existen, cómo se conectan y cómo se agrupan; la plataforma las coloca. Sin coordenadas, sin SVG hecho a mano, sin arte de texto. Cada diagrama es un fichero propio, `diagramas/<id>.yaml`, así que se escribe una vez y se muestra donde ayude:

```mdx
<Diagram id="pipeline" />
```

Este es el de la portada de este sitio:

## El fichero

```yaml
# diagramas/komodo.yaml → id: komodo
titulo: Cómo despliega Komodo
descripcion: Komodo le dice a Periphery, en cada servidor, que levante los stacks
direccion: derecha
nodos:
  komodo: { entidad: services/komodo }
  periphery: { nombre: Periphery, sub: agente en cada servidor, tipo: entrada }
  stacks: Stacks
conexiones:
  - komodo -> periphery: deploy
  - periphery -> stacks
zonas:
  home: { titulo: Casa, nodos: [komodo, periphery] }
```

| Clave | Qué es |
| --- | --- |
| `titulo` | Obligatoria. Su título, mostrado como pie. |
| `descripcion` | Obligatoria. Qué muestra, en una o dos frases: es su texto alternativo y lo que leen los agentes. |
| `direccion` | Opcional. `derecha` (de izquierda a derecha, el valor por defecto) o `abajo` (de arriba abajo). Sigue el flujo: una cadena de pasos va a la derecha, una jerarquía va hacia abajo. |
| `nodos` | Obligatoria. Las cajas, por id. |
| `conexiones` | Opcional. Las flechas entre ellas. |
| `zonas` | Opcional. Grupos de cajas con título. |

### Nodos

El id de un nodo va en minúsculas, con dígitos y guiones, y es local al diagrama (`nas`, no `node3`). Un nodo es una de estas cosas:

- **Una entidad del catálogo:** `{ entidad: machines/nas }`. Toma su nombre, su icono y su enlace de la entidad. Úsala siempre que la caja exista en el catálogo: la página de la entidad lista entonces el diagrama.
- **Una caja con nombre:** `{ nombre: Periphery, sub: agente en cada servidor }`. `sub` es una línea corta bajo el nombre.
- **Solo un nombre:** `stacks: Stacks`.

Cualquiera de ellos admite `icono` (el nombre de un icono de Lucide) y `tipo`: `entrada` donde empieza el flujo, `almacen` para datos (discos, registros, bases de datos).

### Conexiones

`origen -> destino`, o `origen -> destino: etiqueta`, con la etiqueta diciendo **qué viaja** por ella, en pocas palabras: "copia de seguridad cifrada cada noche", no "conexión". Ambos extremos son ids de nodo.

### Zonas

Dónde están las cosas (casa, el VPS, fuera) o a qué red pertenecen: un `titulo` y los `nodos` que contiene. Un nodo va como máximo en una zona.

## Qué se reporta

La plataforma valida cada diagrama contra el catálogo. Una entidad que no existe, una conexión a un nodo que no está declarado, un nodo en dos zonas, un título que falta o una clave desconocida se reportan en el fichero **y** en cada página que lo muestra; lo que sea válido se sigue mostrando. Un `Diagram` con un id desconocido muestra un aviso, y un bloque de código con el lenguaje `diagram` dentro de una página se reporta: los diagramas viven en `diagramas/`.

## Cómo se muestra hoy

Hasta que la plataforma dibuje los diagramas, se muestran como texto: su título y su descripción como pie, sus zonas con sus cajas y una línea por conexión ("Autor → Repositorio de contenido: git push"), con cada entidad enlazada a su página. Es también exactamente lo que reciben los agentes en el Markdown de la página. Escribirlos ahora no cuesta nada más adelante: el formato se mantiene.

## Pautas

- **Un diagrama, una idea.** A partir de una docena de nodos, divídelo.
- **Solo las conexiones que importan** para entender la página; el resto va en el texto.
- **Nada sensible** en etiquetas ni subtítulos.
