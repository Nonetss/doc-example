## A file

```yaml
# catalogo/machines/docker-01.yaml → id: docker-01
ip: 192.168.1.20
location: home
kind: vm
host: pve-01
fuente: komodo
actualizado: 2026-10-15
```

- **The id is the file name:** lowercase, digits and hyphens. The extension is `.yaml`, never `.yml`. A file starting with `_` is not an entity.
- **Only the fields its type declares,** every required one included. A `ref` must name an entity that exists, and a `ficha` a page that exists.
- **Provenance:** `fuente` says where the data comes from (`manual`, or the panel it was read from) and `actualizado` its date. When the panel and the catalog disagree, the panel wins: fix the entity.
- **One entity per file,** always, even for long lists.
- **No secret,** not even for now.

An entity that fails its type is left out of every table and reported, and the rest of the catalog is published.

## Citing it from a page

- **In the header,** through a `ref` field declared under `cabecera`: `machines: [docker-01]`.
- **In the text,** with a link: `[docker-01](catalogo:machines/docker-01)`.

Either way, the entity's [catalog page](reader.mdx) lists the page under "Páginas que la citan".

## YAML traps

- Text containing `: ` goes between quotes: `purpose: "The way in: Pangolin"`.
- So does text starting with `[`, `{`, `*`, `&`, `!`, `%` or `@`, and text that reads as `yes`, `no`, `on`, `off`, `null` or a number.
- Dates are always `YYYY-MM-DD`.
- Ports with a slash (`53:53/udp`) go between quotes.

The editor marks all of these as you type: see [The editor](../publishing/editor.mdx).
